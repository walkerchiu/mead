# Welcome to MEAD Storybook

This is the MEAD project's Storybook component library, built on **Atomic Design** principles.

## 🎯 What is Atomic Design?

Atomic Design is a design system methodology that organizes UI components into five levels:

```
Atoms → Molecules → Organisms → Templates → Pages
```

### 📦 Component Levels

#### 1. **Atoms**

The most basic UI elements that cannot be broken down further.

Examples:

- `Button` - Button component
- `TextField` - Input field
- `CodeInput` - Verification code input

**When to use**: When you need the most basic UI elements.

#### 2. **Molecules**

Composed of multiple Atoms with specific functionality.

Examples:

- `FormField` - Form field (TextField + Label + Error)
- `PasswordField` - Password input (TextField + Show/Hide button + Strength indicator)
- `AlertMessage` - Alert message

**When to use**: When you need to combine multiple basic elements for specific functionality.

#### 3. **Organisms**

Complete functional modules composed of Molecules and Atoms.

Examples:

- `LoginForm` - Login form
- `TwoFactorForm` - Two-factor authentication form
- `ForgotPasswordForm` - Forgot password form

**When to use**: When you need complete functional modules (forms, cards, etc.).

#### 4. **Templates**

Define page structure and layout.

Examples:

- `AuthLayout` - Authentication page layout

**When to use**: When you need unified page layouts.

#### 5. **Pages**

Complete page displays (for Storybook only).

Examples:

- `LoginPage` - Complete login page flow
- `ForgotPasswordPage` - Forgot password page

**When to use**: To demonstrate complete user flows and interactions.

## 🚀 Quick Start

### Browse Components

The sidebar is organized into four top-level **scopes**, each with its own
`Overview` page:

1. **Public Scope** - Public, login-free content site (near-term focus, currently empty)
2. **HQ Scope** - Back-office admin; holds the template's full component set today
3. **Customer Scope** - Logged-in customer-facing screens (currently empty)
4. **Shared** - Reserved for genuinely cross-scope components (currently empty)

Inside every scope, components follow the same Atomic Design layering:
**Design System → Atoms → Molecules → Organisms → Layout → Templates → Pages**.

Public Scope and Customer Scope are expected to differ substantially in style,
so the existing template components are treated as HQ-specific rather than
shared. Promote a component to **Shared** only once two or more scopes truly
use it with the same styling.

### Test Components

Each component has multiple **Stories** (scenario displays):

- **Default** - Default state
- **Loading** - Loading state
- **Error** - Error state
- **Interactive** - Interactive example

### Use Controls

Click the **Controls** tab to adjust component props in real-time:

- Modify text content
- Toggle states (disabled, loading)
- Adjust styles (variant, color, size)

## 🛠️ Development Guide

### Story-First Development Flow

1. **Develop UI in Storybook**

   ```bash
   pnpm storybook
   ```

2. **Create Components and Stories**

   ```tsx
   // Button.tsx
   export function Button({ children, loading }) {
     return <MuiButton disabled={loading}>{children}</MuiButton>;
   }

   // Button.stories.tsx
   export const Default: Story = {
     args: { children: 'Click me' },
   };

   export const Loading: Story = {
     args: { children: 'Loading', loading: true },
   };
   ```

3. **Test All States**
   - Preview in Storybook
   - Test different props using Controls
   - Check responsive design

4. **Integrate into Next.js Pages**

   ```tsx
   // app/login/page.tsx
   import { LoginForm } from '@/components/organisms';

   export default function LoginPage() {
     return <LoginForm onSubmit={handleLogin} />;
   }
   ```

### Naming Conventions

- **Components**: PascalCase (e.g., `LoginForm`)
- **Files**: Same as component name (e.g., `LoginForm.tsx`)
- **Stories**: ComponentName.stories.tsx (e.g., `LoginForm.stories.tsx`)

### Directory Structure

```text
src/components/
├── atoms/
│   ├── Button/
│   │   ├── Button.tsx
│   │   └── Button.stories.tsx
│   └── index.ts
├── molecules/
│   ├── FormField/
│   │   ├── FormField.tsx
│   │   └── FormField.stories.tsx
│   └── index.ts
└── organisms/
    ├── LoginForm/
    │   ├── LoginForm.tsx
    │   └── LoginForm.stories.tsx
    └── index.ts
```

## 🎨 Design Principles

### 1. Single Responsibility

Each component does one thing and does it well.

### 2. Composition Over Inheritance

Use composition rather than inheritance to build complex components.

### 3. Props-Driven

Components should be stateless, controlled through props.

### 4. Consistency

Maintain consistency in naming, styling, and behavior.
