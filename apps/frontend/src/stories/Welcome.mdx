# 歡迎使用 MEAD Storybook

這是 MEAD 專案的 Storybook 元件庫，以 **Atomic Design** 原則為基礎建構。

## 🎯 什麼是 Atomic Design？

Atomic Design 是一套設計系統方法論，將 UI 元件組織為五個層級：

```
Atoms → Molecules → Organisms → Templates → Pages
```

### 📦 元件層級

#### 1. **Atoms**

最基本、無法再進一步拆解的 UI 元素。

範例：

- `Button` - 按鈕元件
- `TextField` - 輸入欄位
- `CodeInput` - 驗證碼輸入

**何時使用**：當你需要最基本的 UI 元素時。

#### 2. **Molecules**

由多個 Atoms 組合而成，具備特定功能。

範例：

- `FormField` - 表單欄位（TextField + Label + Error）
- `PasswordField` - 密碼輸入（TextField + 顯示／隱藏按鈕 + 強度指示器）
- `AlertMessage` - 警示訊息

**何時使用**：當你需要組合多個基本元素以達成特定功能時。

#### 3. **Organisms**

由 Molecules 與 Atoms 組合而成的完整功能模組。

範例：

- `LoginForm` - 登入表單
- `TwoFactorForm` - 雙因素驗證表單
- `ForgotPasswordForm` - 忘記密碼表單

**何時使用**：當你需要完整的功能模組（表單、卡片等）時。

#### 4. **Templates**

定義頁面結構與版面配置。

範例：

- `AuthLayout` - 認證頁面版面配置

**何時使用**：當你需要統一的頁面版面配置時。

#### 5. **Pages**

完整的頁面呈現（僅供 Storybook 使用）。

範例：

- `LoginPage` - 完整登入頁面流程
- `ForgotPasswordPage` - 忘記密碼頁面

**何時使用**：用於展示完整的使用者流程與互動。

## 🚀 快速開始

### 瀏覽元件

側邊欄分為三個頂層 **scope**，各自擁有專屬的 `Overview` 頁面：

1. **Public Scope** - 公開、免登入的內容網站（近期主力焦點）
2. **HQ Scope** - 後台管理；運維工具（稽核日誌、Cron Jobs、Session）與 HQ 專屬外殼
3. **Shared** - 跨 scope 的通用 UI 元件與認證流程

在每個 scope 內，元件皆遵循相同的 Atomic Design 分層：
**Design System → Atoms → Molecules → Organisms → Layout → Templates → Pages**。

Scope 由原始碼資料夾決定：scope 專屬元件位於
`components/public/<level>/`（Public）或 `components/<level>/hq/`（HQ）；通用的
共用元件則直接放在 `components/<level>/` 之下。當不確定元件歸屬時，預設放入
**Shared**。

### 測試元件

每個元件都有多個 **Story**（情境展示）：

- **Default** - 預設狀態
- **Loading** - 載入中狀態
- **Error** - 錯誤狀態
- **Interactive** - 互動範例

### 使用 Controls

點選 **Controls** 分頁即可即時調整元件 props：

- 修改文字內容
- 切換狀態（停用、載入中）
- 調整樣式（variant、color、size）

## 🛠️ 開發指南

### Story-First 開發流程

1. **在 Storybook 中開發 UI**

   ```bash
   pnpm storybook
   ```

2. **建立元件與 Story**

   ```tsx
   // Button.tsx
   export function Button({ children, loading }) {
     return <MuiButton disabled={loading}>{children}</MuiButton>;
   }

   // Button.stories.tsx
   export const Default: Story = {
     args: { children: 'Click me' },
   };

   export const Loading: Story = {
     args: { children: 'Loading', loading: true },
   };
   ```

3. **測試所有狀態**
   - 在 Storybook 中預覽
   - 使用 Controls 測試不同的 props
   - 檢查響應式設計

4. **整合至 Next.js 頁面**

   ```tsx
   // app/login/page.tsx
   import { LoginForm } from '@/components/organisms';

   export default function LoginPage() {
     return <LoginForm onSubmit={handleLogin} />;
   }
   ```

### 命名慣例

- **元件**：PascalCase（例如 `LoginForm`）
- **檔案**：與元件名稱相同（例如 `LoginForm.tsx`）
- **Story**：ComponentName.stories.tsx（例如 `LoginForm.stories.tsx`）

### 目錄結構

```text
src/components/
├── atoms/
│   ├── Button/
│   │   ├── Button.tsx
│   │   └── Button.stories.tsx
│   └── index.ts
├── molecules/
│   ├── FormField/
│   │   ├── FormField.tsx
│   │   └── FormField.stories.tsx
│   └── index.ts
└── organisms/
    ├── LoginForm/
    │   ├── LoginForm.tsx
    │   └── LoginForm.stories.tsx
    └── index.ts
```

## 🎨 設計原則

### 1. 單一職責

每個元件只做一件事，並把它做好。

### 2. 組合優於繼承

使用組合而非繼承來建構複雜的元件。

### 3. Props 驅動

元件應為無狀態，透過 props 控制。

### 4. 一致性

在命名、樣式與行為上維持一致性。
