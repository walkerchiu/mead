## 標題層級

- `#` H1：每個檔案 **唯一一個**，做為文件標題
- `##` H2：主章節（最常用）
- `###` H3：子章節
- `####` H4：細節（盡量避免，能用 H3 就用 H3）
- 不用 `#####` / `######`

**H1 後請接一段一句話的簡介**：

```markdown
# 文件標題

這個文件做什麼的，一句話說完。

---

## 第一個章節
```

H2 之間用 `---` 分隔線可選；長文件建議用，短文件可省略。

## Emoji 使用原則

**核心原則：非必要不用 emoji。** 以文字為主，emoji 只在有功能性語意時使用。

### 不要使用的場景

- ❌ H1 / H2 / H3 / H4 標題前綴（例：`## 📋 目錄` → `## 目錄`）— **所有 emoji 一律移除，包含狀態符號**
- ❌ 段落內的裝飾（例：`啟動服務 🚀` → `啟動服務`）
- ❌ 列表項目開頭的裝飾（例：`- 📦 套件` → `- 套件`）
- ❌ 連結文字內的裝飾（例：`[📋 目錄](#目錄)` → `[目錄](#目錄)`）
- ❌ 表格欄位中的裝飾性 emoji

### 允許使用的場景（有功能語意）

僅以下狀態符號允許在 **內文**（非 H 標題）出現，傳達 **狀態判讀** 而非裝飾：

| 用途        | 符號 | 範例              |
| ----------- | ---- | ----------------- |
| 完成 / 正常 | ✅   | `✅ 全部測試通過` |
| 失敗 / 錯誤 | ❌   | `❌ 連線失敗`     |
| 警告        | ⚠️   | `⚠️ 此操作不可逆` |

**不要使用 cli 字元**：`✓` `✗` `✘` `⚠` `✔`（這些是 cli 樣式字元，不是 markdown 樣式字元）。

> **重要**：如果 markdown 是在描述 cli 工具的行為（例如 `cli.sh status` 真實輸出），**code block 內** 保留 cli 原 char（`✓` / `✗`）忠實呈現實際 output。code block 外才用 `✅` / `❌`。

### 為什麼不用裝飾 emoji

- **可讀性**：純文字標題在不同終端 / 編輯器 / Git diff 渲染都一致
- **搜尋友善**：搜尋「快速開始」比搜尋「🚀 快速開始」直觀
- **跨平台一致**：emoji 在不同字型 / 系統渲染差異大
- **降噪**：技術文件以資訊密度為先，視覺效果其次

## 編排與排版

### 列表

bullet 一律使用 `-`（不用 `*` 或 `•`）：

```markdown
- 第一項
- 第二項
  - 巢狀用兩格縮排
- 第三項
```

### 表格

由 prettier 自動 align（`pnpm format` 會處理）。手寫時不需要對齊，prettier 會自動補空格。

### 強調

- **粗體** 用於重點概念或服務名稱：`**MikroORM**`
- _斜體_ 用於專有名詞或暫態描述（少用）
- `inline code` 用於命令、檔名、識別符

### 引用 / 註解

- `>` 用於補充說明、警告、注意事項
- 多行引用每行都要 `>`

### Task list（待辦事項）

GitHub 的 task list 語法 — 中括號裡 **必須有一個空格**：

```markdown
- [ ] 未完成項
- [x] 已完成項（小寫 x）
```

注意 `- [ ]`（中括號內含空格）才會渲染成 checkbox；`- []`（無空格）會被當作普通連結文字，**不正確**。

### 目錄章節

H2/H3 章節數 ≥ 3 個的文件應加 `## 目錄`，置於 H1 + 簡介 + `---` 之後：

```markdown
# 文件標題

簡介一句。

---

## 目錄

- [章節 1](#章節-1)
  - [子章節](#子章節)
- [章節 2](#章節-2)

---

## 章節 1
```

**例外**：索引型文件（如 `docs/README.md` 這類本身就是文件總覽）不需要額外的 `## 目錄`，因其全部章節都是目錄性質。

### 分隔線

H1 / H2 之間用 `---`（前後各一空行）。

## 程式碼塊

**一律標註語言**：

````markdown
```bash
./scripts/cli.sh dev
```

```ts
const x = 1;
```

```json
{ "key": "value" }
```

```text
非程式碼的等寬輸出（如 cli 樣式輸出、目錄樹）
```
````

支援的語言：`bash` / `sh` / `ts` / `tsx` / `js` / `jsx` / `json` / `yaml` / `text` / `markdown` / `dockerfile` / `sql` / `graphql` 等。

---

## 連結與參考

- 內部連結用相對路徑：`[見 CLI 指南](./CLI_GUIDE.md)`
- 外部連結用完整 URL：`[Next.js Docs](https://nextjs.org/docs)`
- 同檔內錨點用 `#章節名`：`[跳到目錄](#目錄)`

---

## 中英文混排

中文與英文 / 數字之間留半形空格：

- ✅ `Next.js 16 是最新版本`
- ❌ `Next.js16是最新版本`

例外：標點符號緊鄰的不需要空格（`Next.js，最強框架`）。

## 自動化檢查

```bash
# 全 repo 跑 prettier 對齊（會自動修排版、bullet、行尾空白等）
pnpm format

# 只檢查不改
pnpm format:check
```

> 規範未涵蓋的細節以 prettier 自動格式化結果為準。
